# ARCHITECTURE.md

## Overview

```
Flutter app (Android)  --HTTPS-->  FastAPI backend (Render free)  --API-->  Gemini
   - UI, STT (on-device)             - holds GEMINI_API_KEY
   - local settings                  - builds prompts, validates JSON
                                     - per-device rate limit
```

The backend is a thin proxy. It has **no database** in the MVP.

## Backend details

### Environment variables

| Name | Purpose | Example |
|---|---|---|
| `GEMINI_API_KEY` | Gemini key (secret) | set on Render only |
| `GEMINI_MODEL` | Model id, default a current Flash-Lite model | check AI Studio |
| `DAILY_LIMIT` | Max AI requests per device per day | `60` |
| `APP_TOKEN` | Shared token the app sends in `X-App-Token` | random string |

### Request handling

1. Read headers `X-Device-Id` (random UUID generated by the app on first launch) and `X-App-Token`.
2. Reject with 401 if the token is wrong, 429 if the device exceeded `DAILY_LIMIT`.
3. Build the prompt from the request fields (see `PROMPTS.md`).
4. Call Gemini once, requesting JSON that matches the response Pydantic model.
5. Validate the output. If invalid, retry **once**; if still invalid, return a 502 with the error format below.
6. Return the validated JSON.

The rate limiter is in memory. It resets when the free instance restarts; that is acceptable for the MVP.

`APP_TOKEN` is only a light deterrent (it can be extracted from the APK). It is not real authentication. Real protection is the rate limit and Gemini's own quotas.

### Error format (all endpoints)

```json
{ "error": { "code": "rate_limited", "message": "Daily limit reached. Please try again tomorrow." } }
```

Codes: `unauthorized`, `rate_limited`, `bad_request`, `ai_unavailable` (Gemini error or quota exhausted), `ai_invalid_output`.

### Health endpoint

`GET /health` returns `{"status":"ok"}`. Used by the app to wake the server (call it at app start, in the background).

### Logging

Log request path, status, latency, device id hash. Do **not** log user message contents or the API key.

## Flutter details

### Screens

1. **Onboarding** (first launch): goal -> level -> explanation language.
2. **Home**: three big cards (Conversation, Vocabulary Quiz, Speaking Practice) and a settings icon.
3. **Conversation**: chat list, input box, quick topic chips when empty, correction card under AI bubbles.
4. **Quiz**: one question at a time, 4 option buttons, immediate feedback + explanation, running score, result screen.
5. **Speaking**: theme picker -> prompt screen with mic button -> editable transcript -> feedback screen.
6. **Settings**: change goal, level, explanation language.

### Local storage (`shared_preferences`)

| Key | Value |
|---|---|
| `goal` | `exam_prep` or `career` |
| `level` | `beginner`, `intermediate`, `advanced` |
| `explanation_language` | `id` or `en` |
| `device_id` | UUID string, generated once |

No other persistence in the MVP.

### Speech-to-text flow

1. Request the mic permission (Android `RECORD_AUDIO`).
2. Start listening with locale `en_US`.
3. Show live partial text. When the user stops, show the final transcript in an **editable** text field with "Re-record" and "Submit" buttons.
4. Send only the transcript text to the backend.

### Networking

- Base URL comes from a build-time constant (`--dart-define=API_BASE_URL=...`).
- On app start, fire a background `GET /health` to wake the server.
- Timeout 60 s. On timeout or network error show a retry button.

## Security summary

- API key only on the backend (Render environment variable).
- Repo must contain `.env.example` only; `.env` is in `.gitignore`.
- Play Store release will require a privacy policy. Note: Gemini free-tier data may be used by Google to improve its products; mention AI processing of user text in the privacy policy.
